# 脚本内请求

脚本不能直接使用浏览器的 `fetch`。它调用：

```js
const cancel = lx.request(url, options, (err, resp, body) => {})
```

`options`：

| 字段 | 说明 |
|---|---|
| `method` | 默认 `get` |
| `timeout` | 大于 0 的数字才生效，上限 60 秒。未传时宿主用 13 秒 |
| `headers` | 与默认头合并。默认 `User-Agent` 是一套 Chrome 69 字符串，默认 `Accept` 是 `application/json` |
| `body` | `POST` 且未设 `Content-Type` 时按 JSON 发送，并补上 `application/json` |
| `form` | 同上条件下改为 `application/x-www-form-urlencoded` |
| `formData` | 原样作为正文，`Content-Type` 设为 `multipart/form-data` |
| `binary` | 为 `true` 时正文是二进制缓冲区，不做 JSON 解析 |

成功时 `err` 为 `null`。`resp` 与第三个参数 `body` 的正文相同：

| 字段 | 说明 |
|---|---|
| `statusCode` | HTTP 状态码 |
| `statusMessage` | 状态文本 |
| `headers` | 响应头 |
| `body` | 能解析则是 JSON，否则保留文本。`binary: true` 时是缓冲区 |
| `url` | 最终地址。这一字段在原生响应里有，回调里的 `resp` 目前没有把它拷贝出来 |
| `ok` | 是否为成功状态。同样只在原生响应里，回调对象未拷贝 |

返回的函数可取消这次请求。

这是脚本与网络之间的形状。脚本从自己的服务器拿到 JSON 之后，仍要按 [动作与响应](./03-动作与响应.md) 返回字符串或歌词对象。服务器若使用 `{ code, url }` 或 `{ code, data: { url } }`，那是该脚本自己的约定，换一个脚本就可以不同。
